## Observed facts (already recorded, unchanged)

On the isolated source-only defect tree `24f225d4` (diff: `extensions/gsd/wave-status.rkt` only),

## The four data sets in the pipeline

| Set | Where it comes from | Size at `a7e14a25` |
|---|---|---|
| Audited owners (the **selectable universe**) | hand-written table `current-admitted-owners`, `scripts/testing/quick-audit.rkt` | **23** |
| Declared `@covers` attribution | generated `tests/.coverage-manifest.json`, loaded by `load-coverage-manifest`, `scripts/testing/changed-selection.rkt` | **226 tests → 202 modules** |
| Impact dependency graph | `build-dependency-graph` over production files | 0 parse failures |
| Admission record (`tests/.quick-admission.rktd`) | per-owner closure + hashes + scan verdict, generated by `refresh-record!` | 23 owners |

These sets are **independent by design**. `@covers` is selection metadata; the owner table is a
human-reviewed capability/boundary allow-list (§ "1. THE REVIEWED OWNER TABLE" in
`quick-audit.rkt`). Coverage never creates an owner, and the owner table never consults `@covers`.

## Pipeline trace for D5, with code-level evidence

1. **Changed set.** `quick-changed-owners` (`scripts/testing/full-plan.rkt`) calls
   `changed-selection` with `rels` = the 23 audited owners. The selector can only ever run a test
   that is in `rels`.
2. **Attribution.** The manifest maps `extensions/gsd/wave-status.rkt` →
   `tests/test-gsd-wave-status.rkt`, `tests/test-audit-v09945-w3-gsd.rkt`
   (`build-dependency-graph`-independent; verified by loading the manifest).
   **Neither is in `rels`.** Every `.rkt` test with `@covers` is in the manifest, but only 23 tests
   are selectable.
3. **Selection.** `compute-impact-selection` walks direct covers and transitive dependents of
   `wave-status.rkt`. The only selected file is
   `tests/test-gsd-campaign-decision-pure.rkt` (a dependent's audited cover). The module's own
   detectors are outside the universe, so they are dropped when the selection is intersected with
   `rels` — silently.
4. **Escalation.** `unmapped-source` fires only when
   `(and (null? direct) (not any-covered-dependent?))`, where `direct = (hash-ref module->tests m)`
   is built from **the whole manifest**, not from `rels`. For `wave-status.rkt` `direct` is
   non-empty (two unaudited tests), so the condition is false and **no escalation is emitted**.
   The rule therefore cannot detect "declared but not selectable".
5. **Consumer-contract escalation.** There is no such rule in the selector. The complete escalation
   vocabulary at `a7e14a25` is `runner-helper-change`, `config-change`, `fixture-change`,
   `generated-code`, `graph-parse-failure`, `unmapped-source`, and the `source-escalation-scan`
   codes (dynamic-require, macro-change, #lang reader). The corpus's expected
   "consumer-contract escalation (vocabulary fan-in)" has **no implementation**.
6. **Fail-open inclusions.** `changed-selection` includes any audited owner with no `@covers`
   attribution (`(not (attributed? rel))` → included). Two owners are in that state
   (`tests/test-agent-memory-decoupling.rkt`, `tests/test-agent-session-config.rkt`), so they run on
   every change: noise, not signal. That is exactly the two "no @covers attribution; fail open"
   lines in the D5 plan.

## Why does `@covers` exist without corresponding audited ownership?

Because admission and attribution answer different questions:

- `@covers` answers "which test is *supposed* to detect a change to this module?" — declared by the
  test author, machine-collected, never verified against execution.
- The owner table answers "which test may `./qt quick` *run* without renewed review?" — a manual,
  capability-scanned allow-list of pure unit tests (`@boundary unit`, `@speed fast`, no
  filesystem/network/process/eval in the file or its reviewed closure).

The selector intersects them implicitly (via `rels`) and never checks that the intersection is
non-empty for a changed module.

## Is `tests/test-gsd-wave-status.rkt` intentionally excluded, stale, or misclassified?

**None of those: it is eligible but unadmitted.** Direct evidence:

- it declares `;; @covers extensions/gsd/wave-status.rkt`, `;; @speed fast`, `;; @boundary unit`;
- its reviewed closure is 2 files (`tests/test-gsd-wave-status.rkt`,
  `extensions/gsd/wave-status.rkt`) and the capability denylist scan returns **no hits**;
- `owner-admission-state` returns `rejected — "not an admitted owner (review the table to admit
  it)"`, i.e. the *only* obstacle is the hand-curated table.

History gives the second half of the story: commit `9f292394` (#9970, "retire global scans and
archival audits from everyday lane") removed `tests/test-audit-v09945-w3-gsd.rkt` — the other
declared cover of `wave-status.rkt` — from the owner table. After that retirement the module had
**zero selectable detectors**, and nothing in the pipeline re-checks selectability. Two modules
(`extensions/gsd/session-state.rkt`, `extensions/gsd/transition-logic.rkt`) are in the same
"retired-cover-only" state today.

## Confirmed mechanism vs hypotheses

Confirmed by reading and executing the shipped code:

- selection universe = audited owners; attribution = full manifest; the intersection is never
  validated;
- `unmapped-source` inspects declared covers, not selectable ones, so it cannot catch this;
- no consumer-contract escalation exists;
- audited owners without `@covers` are included unconditionally;
- `test-gsd-wave-status.rkt` is capability-clean and rejected only by table membership.

Not established (and not claimed):

- whether the D5 behaviour would have been caught by the *selected* set if the test had been
  admitted (not measured; the test was never run in the experiment);
- whether `@covers` entries are behaviourally accurate across the repo (declared, not verified);
- whether a developer would have updated the admission record in a real change (the experiment used
  the documented refresh workflow; the preparation difference is recorded in the W2 report).

## Consequences for the acceptance criteria

`./qt quick` is documented in code as "reproduction only, never a PR/CI claim". The D5 result shows
that when it is used as a verdict (the CL5 hypothesis), a change to a covered-by-non-audited-tests
module yields a **green with no detector**. That is the zero-missed-defects criterion failing, not a
tuning problem: 176 of 202 covered modules are in this state today (see the coverage-gap audit).

## Exact conditions to treat W2 as resumable

1. The guard (or an equivalent) refuses a "selected" verdict whenever a changed module has declared
   coverage but no selectable detector.
2. Ownership evidence for the changed module is verifiable (owner table + admission record fresh) or
   the selector escalates.
3. A zero-test selection can never be reported as green.
4. The D5 negative control and a clean control both pass offline (already true for the isolated
   prototype; see `scripts/cl5/selection-guard.rkt` and its tests).
5. Matched-host cost evidence still requires GitHub Actions to return; until then the 40 % target
   stays unproven.
