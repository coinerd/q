## Protocol corrections implemented in this round

1. **Shadow-selected execution is measured, not inferred.** `run-case-ci` runs
   `./qt quick --changed HEAD --explain` and `./qt quick --changed HEAD` on the injected tree
   **before** committing, records selected files, escalations, exit, duration, timeout and failure
   identity, then commits the same tree and matches CI by SHA. Classification is now
   `classify-case-evidence(selected-defect, selected-control, ci-defect, ci-control)`:
   `detected` requires both surfaces to fail and both controls to pass; `missed` is selected-pass
   with comprehensive-fail; anything else is `unavailable` or `not-detected`.
2. **Clean control is matched, not empty.** A clean tree has an empty diff, and the selector rightly
   treats a zero selection as a failure. The control therefore runs the **same selected file set**
   the defect shipped against the clean source, per file (`./qt full --file …`), and must pass.
3. **Fail-closed CI completeness.** All 14 required producers must be *present* and `success`;
   a missing or duplicated job name, a skipped/cancelled/in-progress producer, or a non-completed
   run is `unavailable`. The four dispatch-expected skips (`fast-env`, `gsd-governance`,
   `release-readiness`, `workflows-aggregate`) must still appear in the job list. Job retrieval
   follows pagination.
4. **Exception-safe scratch state.** A `dynamic-wind` resets the worktree, deletes the local branch
   and the remote scratch branch whatever happens during dispatch or job retrieval; per-state
   records are appended to a checkpoint file outside the worktree.
5. **Tree identity is bound.** `measured-tree-sha` and `committed-tree-sha` are recorded for each
   state; here they are equal (`6fe78f9b…` / `aaf60973…`), so the CI SHA provably carries exactly
   the tree that was measured. Admission refresh happens inside the state, derived records are
   restored before committing, and a refusal (`quick refuses`) is `unavailable`, never a pass.
