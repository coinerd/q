## Provenance correction (this round)

The previous run committed a **two-file** state (`tests/.quick-admission.rktd` leaked in, tree
`6fe78f9b…`). Root cause, confirmed by the reviewer: `measure-selected!` staged the refreshed
admission record (`git add -A`) and then restored with `git checkout -- <file>`, which restores from
the **index**, not the pinned commit — so the staged refresh survived. The second `write-tree`
therefore matched the first, giving a false identity proof.

Fixes:

- `restore-derived-files!` now uses
  `git restore --source=<revision> --staged --worktree -- <admission files>`, which resets index and
  worktree. A regression test builds a real temporary repository, stages a refresh, restores, and
  asserts both `git status --porcelain` and `git diff --cached --name-only` are empty and the file
  content is the committed one.
- `measure-selected!` asserts the committed tree changes **exactly** the registered files
  (`declared-changes` from the frozen registry; empty for a clean control) and records
  `committed-changes` plus `provenance-ok?`. `run-case-ci` **raises before dispatching** when the
  check fails, so a non-comparable tree can never become evidence.
- The repaired defect tree is now `24f225d4…`, **identical** to the source-only D5 tree of the
  historical CI run 45043919793. That verdict is reused and keyed by tree sha
  (`ci-source: cache`); no new dispatch was needed (GitHub Actions is under a billing restriction).
