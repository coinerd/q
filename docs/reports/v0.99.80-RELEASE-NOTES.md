# Release Notes — v0.99.80

## `/go` Wave Campaign Orchestration

This release transforms `/go` from an all-waves-in-one-agent-run model into a durable, verifiable, wave-at-a-time campaign coordinator.

### Key Changes

#### Durable Campaign State (W0)
- New `extensions/gsd/campaign-state.rkt` module providing immutable manifest identity, canonical status mapping (7 statuses), migration truth, and atomic persistence.
- Plan ID is SHA-256 of an immutable manifest. Status-only edits preserve identity; substantive edits pause as PLAN-CHANGED.
- Migration from PLAN.md/STATE.md with fail-closed conflict detection.
- One-active-wave invariant enforced.

#### Verifier-First Completion (W1)
- New `extensions/gsd/wave-completion.rkt` module.
- No production path can persist DONE before evidence is verified.
- Verifier rejection marks FAILED; never DONE.
- Durable completion outbox with stable event IDs and deduplication.
- Removed unsafe auto-completion heuristics from `archive.rkt` (GC-5 regression fix).

#### Single-Wave Campaign Coordinator (W2)
- New `extensions/gsd/go-orchestrator.rkt` module.
- One wave per prompt invocation, enforced at runtime.
- Process-safe OS advisory lease prevents overlapping campaigns.
- `/go N` assertion-only: cannot bypass dependencies.
- Fencing tokens guard against stale results.
- Failure/cancellation stops campaign advancement.
