The `fast/batch/fifo` row is the required-lane baseline already produced by
normal CI; the other three are shadow configurations driven by
`.github/workflows/test-scheduler-cohort-c1.yml`, a `workflow_run` driver
that fires on every successful canonical CI completion on `main`, plans the
missing cohort cells from `cohort.json`, and calls the reusable
`.github/workflows/test-scheduler-shadow.yml` once per cell — every paired
configuration runs automatically on each cohort SHA without manual dispatch.
The reusable workflow itself keeps the W5 trigger contract (`workflow_call`
+ `workflow_dispatch` only) and is governance-pinned by
`tests/test-scheduler-shadow-workflow.rkt`.

## Inventory equality

`report.md` is generated with `--check`: for every configuration and SHA the
selected-file inventory digest is compared against the required-lane
(`fast/batch/fifo`) inventory digest for the same SHA. Any mismatch is a cohort
error (`inventory mismatch ... — cohort error, never silently ignored`). The
current run exits 0 with all 20×4 inventories equal.

## Run IDs

Per-SHA `attempts` entries in `cohort.json` record workflow `run-id`,
`result`, `timing-sample`, and `elapsed-seconds`. This start record was
produced in the local delivery environment; run IDs recorded here are
manifest-bookkeeping placeholders pending the first scheduled activation of
the shadow workflow on GitHub after merge. W1 re-validates every run ID
against the GitHub API before closing the cohort and must replace any
placeholder with a real run before promotion decisions.
